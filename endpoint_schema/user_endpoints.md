# Public and catalogue endpoints

Conventions used in all endpoint files:

- `X?` means the field is optional or nullable. `List[X]` is a JSON array.
- `Time` and `DateTime` values carry a UTC offset, e.g. `08:00:00+01:00`.
- Endpoints that only read data use `GET` and take no body: the id of a single resource goes in the path (`GET /groups/{group_id}`), optional filters go in the query string (`GET /subjects?name=...`). Endpoints that change data use `POST` with a JSON body.
- Every endpoint except `POST /login` needs an `Authorization: Bearer <token>` header. `$student_idx`, `$teacher_idx` and similar "caller" parameters come from that token, not from the request.
- `$id` parameters in `CREATE` queries are UUIDs generated by the server.
- All paths are relative to `/api`, e.g. `GET /subjects` is served at `/api/subjects`. Every other path belongs to the frontend.
- Success: `200 OK` with the resource; `201 Created` when a resource was created (with a `Location` header pointing at its `GET` endpoint, where one exists); `204 No Content` when there is nothing to return.
- Errors are always `{"detail": String}` with a status code that says what went wrong:
  - `400` - the database rejected a parameter (e.g. an invalid date),
  - `401` - missing or invalid token, or wrong email or password,
  - `403` - the caller's role or relations do not allow the operation,
  - `404` - a resource named in the path or the body does not exist,
  - `409` - the operation conflicts with the current state (duplicate, full group, last role),
  - `422` - the values are invalid (wrong type or format, or a rule such as `end_date` after `start_date`); FastAPI's own validation errors have `detail` as a list of `{loc, msg}`,
  - `500` - unexpected server or database error.

## POST /login

**Allowed:** anyone (no token required)

**Request**

```json
{
	"email": String,
	"password": String
}
```

**Response**

```json
{
	"email": String,
	"idx": String?,
	"roles": List["Admin" | "Teacher" | "Student"],
	"token": String
}
```

`401` if the email or password is wrong. `403` if the account has the `Inactive` label or the person has no role.

**Query**

```cypher
MATCH (u:User {email: $email})
RETURN
  u.passwd_hash AS passwd_hash,
  u.email AS email,
  u.idx AS idx,
  u:Inactive AS inactive,
  u:Admin AS admin,
  u:Teacher AS teacher,
  u:Student AS student
```

## GET /teachers

**Allowed:** Student, Teacher, Admin

**Request**

No body; parameters go in the URL:

```http
GET /teachers?name=kowal
```

- `name` (query, optional): part of the name or surname.

**Response**

```json
{
	"teachers": List[Teacher]

	Teacher = {
		"idx": String,
		"name": String,
		"surname": String,
		"phone": String,
		"degree": String,
		"photo": String?,
		"working_since": Date,
		"faculty": String
	}
}
```

**Query**

```cypher
MATCH (t:Teacher)
WHERE $name IS NULL
   OR toLower(t.name + " " + t.surname) CONTAINS toLower($name)
OPTIONAL MATCH (t)-[:WORKS_AT]->(fa:Faculty)
RETURN
  t.idx AS idx,
  t.name AS name,
  t.surname AS surname,
  t.phone AS phone,
  t.degree AS degree,
  t.photo AS photo,
  t.working_since AS working_since,
  fa.name AS faculty
ORDER BY t.surname, t.name
```

## GET /subjects

**Allowed:** Student, Teacher, Admin

**Request**

No body; parameters go in the URL:

```http
GET /subjects?name=sieci&code=SI00
```

- `name` (query, optional): part of the subject name.
- `code` (query, optional): part of the subject code.

**Response**

```json
{
	"cycle_columns": List[String],
	"subjects": List[SubjectCatalogueItem]

	SubjectCatalogueItem = {
		"code": String,
		"name": String,
		"ects": Integer?,
		"faculty": String,
		"cycles": List[SubjectCycleCell]
	}

	SubjectCycleCell = {
		"offered": Boolean,
		"group_count": Integer,
		"registration_open": Boolean
	}
}
```

`cycles[i]` belongs to the cycle named in `cycle_columns[i]`. Columns are in chronological order (`Z` before `L` within a year). A subject is offered in a cycle when some curriculum term taught in that cycle includes it. Registration is open when the current time falls within the period of a registration that opens one of the subject's groups in that cycle. A registration has no dates of its own: its period runs from the start of its first turn to the end of its last one.

**Query**

The server runs two queries. The first one returns the columns; the server sorts them and passes their ids to the second one as `$cycle_ids`. The second one returns one row per subject, with one cell per cycle in the same order as the columns.

```cypher
// 1. Columns: all academic cycles (sorted by the server)
MATCH (ac:AcademicCycle)
RETURN ac.id AS id, ac.year AS year, ac.season AS season

// 2. Matching subjects, each with its faculties and one cell per cycle
MATCH (su:Subject)
WHERE ($name IS NULL OR toLower(su.name) CONTAINS toLower($name))
  AND ($code IS NULL OR toLower(su.code) CONTAINS toLower($code))
RETURN
  su.code AS code,
  su.name AS name,
  su.ects AS ects,
  COLLECT {
    MATCH (su)<-[:INCLUDES]-(:CurriculumTerm)<-[:HAS_TERM]-(:Curriculum)<-[:HAS_CURRICULUM]-(:Programme)-[:OFFERED_BY]->(fa:Faculty)
    RETURN DISTINCT fa.name
  } AS faculties,
  [cycle_id IN $cycle_ids | {
    offered: EXISTS {
      (su)<-[:INCLUDES]-(:CurriculumTerm)-[:TAUGHT_IN]->(:AcademicCycle {id: cycle_id})
    },
    group_count: COUNT {
      (su)<-[:INSTANCE_OF]-(si:SubjectInstance)-[:OFFERED_IN]->(:AcademicCycle {id: cycle_id}),
      (si)-[:HAS_TYPE]->(:GroupType)<-[:OF_TYPE]-(:Group)
    },
    registration_open: EXISTS {
      MATCH (su)<-[:INSTANCE_OF]-(si:SubjectInstance)-[:OFFERED_IN]->(:AcademicCycle {id: cycle_id}),
            (si)-[:HAS_TYPE]->(:GroupType)<-[:OF_TYPE]-(:Group)<-[:OPENS]-(reg:Registration)-[:HAS_TURN]->(rt:RegistrationTurn)
      WITH reg,
           min(datetime({date: rt.date, time: rt.start_time})) AS opens,
           max(datetime({date: rt.date, time: rt.end_time})) AS closes
      WHERE opens <= datetime() < closes
    }
  }] AS cycles
ORDER BY su.name
```

## GET /faculties

**Allowed:** Student, Teacher, Admin

**Request**

No body; parameters go in the URL:

```http
GET /faculties?name=W04
```

- `name` (query, optional): part of the short or full faculty name.

**Response**

```json
{
	"faculties": List[Faculty]

	Faculty = {
		"id": String,
		"name": String,
		"full_name": String
	}
}
```

**Query**

```cypher
MATCH (fa:Faculty)
WHERE $name IS NULL
   OR toLower(fa.name) CONTAINS toLower($name)
   OR toLower(fa.full_name) CONTAINS toLower($name)
RETURN fa.id AS id, fa.name AS name, fa.full_name AS full_name

```

## GET /curricula

**Allowed:** Student, Teacher, Admin

**Request**

No body; parameters go in the URL:

```http
GET /curricula?name=informatyka
```

- `name` (query, optional): part of the programme name.

**Response**

```json
{
	"curricula": List[Curriculum]

	Curriculum = {
		"id": String,
		"programme_id": String,
		"name": String,
		"intake_year": String
	}
}
```

**Query**

```cypher
MATCH (p:Programme)-[:HAS_CURRICULUM]->(c:Curriculum)
WHERE ($name IS NULL OR toLower(p.name) CONTAINS toLower($name))
RETURN
  c.id AS id,
  p.id AS programme_id,
  p.name AS name,
  c.intake_year AS intake_year
ORDER BY p.name, c.intake_year DESC
```

## GET /subjects/{code}

**Allowed:** Student, Teacher, Admin

**Request**

No body; parameters go in the URL:

```http
GET /subjects/W04CBE-SI0005G
```

- `code` (path): subject code.

**Response**

```json
{
	"code": String,
	"name": String,
	"ects": Integer?,
	"taught_by": List[TeacherName],
	"offerings": List[SubjectOffering]

	TeacherName = {
		"id": String,
		"name": String
	}

	SubjectOffering = {
		"cycle_id": String,
		"cycle": String,
		"group_count": Integer
	}
}
```

Returns 404 if the subject does not exist. `offerings` are in chronological order.

**Query**

```cypher
// 1. Subject and everyone who teaches any of its groups
MATCH (s:Subject {code: $code})
RETURN
  s.code AS code,
  s.name AS name,
  s.ects AS ects,
  COLLECT {
    MATCH (s)<-[:INSTANCE_OF]-(:SubjectInstance)-[:HAS_TYPE]->(:GroupType)<-[:OF_TYPE]-(:Group)<-[:TEACHES]-(t:Teacher)
    RETURN DISTINCT {id: t.idx, name: t.name + " " + t.surname}
  } AS taught_by

// 2. Cycles the subject is offered in, with group counts (sorted by the server)
MATCH (s:Subject {code: $code})<-[:INCLUDES]-(:CurriculumTerm)-[:TAUGHT_IN]->(ac:AcademicCycle)
WITH DISTINCT s, ac
RETURN
  ac.id AS cycle_id,
  ac.year AS cycle_year,
  ac.season AS cycle_season,
  COUNT {
    (s)<-[:INSTANCE_OF]-(si:SubjectInstance)-[:OFFERED_IN]->(ac),
    (si)-[:HAS_TYPE]->(:GroupType)<-[:OF_TYPE]-(:Group)
  } AS group_count
```

## GET /subjects/{code}/groups

**Allowed:** Student, Teacher, Admin

**Request**

No body; parameters go in the URL:

```http
GET /subjects/W04CBE-SI0005G/groups?cycle_id=e3efab49-3222-58a3-a329-2bf8c5d9a363
```

- `code` (path): subject code.
- `cycle_id` (query, required): academic cycle id.

**Response**

```json
{
	"name": String,
	"subject_code": String,
	"cycle_id": String,
	"cycle": String,
	"groups": List[GroupTracked]

	GroupTracked = {
		"id": String,
		"weekday": Integer,
		"g_type": String,
		"number": Integer,
		"pnp": String,
		"capacity": Integer,
		"start_time": Time,
		"end_time": Time,
		"cycle": String,
		"room": String,
		"filled": Integer
	}
}
```

Returns 404 if the subject has no groups in that cycle.

**Query**

```cypher
MATCH (su:Subject {code: $subject_code})<-[:INSTANCE_OF]-(si:SubjectInstance)-[:OFFERED_IN]->(ac:AcademicCycle {id: $cycle_id})
MATCH (si)-[:HAS_TYPE]->(gt:GroupType)<-[:OF_TYPE]-(g:Group)
OPTIONAL MATCH (g)-[:IN_ROOM]->(r:Room)
RETURN
  su.name AS subject_name,
  su.code AS subject_code,
  ac.id AS cycle_id,
  ac.year AS cycle_year,
  ac.season AS cycle_season,
  g.id AS id,
  g.weekday AS weekday,
  gt.g_type AS g_type,
  g.number AS number,
  g.pnp AS pnp,
  g.capacity AS capacity,
  g.start_time AS start_time,
  g.end_time AS end_time,
  r.building AS building,
  r.room_num AS room_num,
  COUNT { (g)<-[:REGISTERED_IN]-(:Student) } AS filled
ORDER BY gt.g_type, g.weekday, g.start_time, g.number
```

## GET /groups/{group_id}

**Allowed:** Student, Teacher, Admin

**Request**

No body; parameters go in the URL:

```http
GET /groups/96992b82-07dc-58c0-b3bf-4d64e58ad87f
```

- `group_id` (path): group id.

**Response**

```json
{
	"subject_code": String,
	"course_name": String,
	"g_type": String,
	"academic_cycle": String,
	"group_num": Integer,
	"weekday": Integer?,
	"pnp": String,
	"start_time": Time?,
	"end_time": Time?,
	"room": String,
	"building": String,
	"nearest_classes": List[ClassOccurrence],
	"filled": Integer,
	"capacity": Integer,
	"teachers": List[TeacherName]

	ClassOccurrence = {
		"class_date": Date,
		"class_start": Time,
		"class_end": Time,
		"building": String
	}

	TeacherName = {
		"id": String,
		"name": String
	}
}
```

Returns 404 if the group does not exist. `nearest_classes` is always empty for now.

**Query**

```cypher
MATCH (g:Group {id: $group_id})-[:OF_TYPE]->(gt:GroupType)<-[:HAS_TYPE]-(si:SubjectInstance)
MATCH (si)-[:INSTANCE_OF]->(su:Subject)
MATCH (si)-[:OFFERED_IN]->(ac:AcademicCycle)
OPTIONAL MATCH (g)-[:IN_ROOM]->(r:Room)
RETURN
  su.code AS subject_code,
  su.name AS course_name,
  gt.g_type AS g_type,
  g.number AS group_num,
  g.weekday AS weekday,
  g.pnp AS pnp,
  g.start_time AS start_time,
  g.end_time AS end_time,
  g.capacity AS capacity,
  r.building AS building,
  r.room_num AS room_num,
  ac.year AS cycle_year,
  ac.season AS cycle_season,
  COUNT { (g)<-[:REGISTERED_IN]-(:Student) } AS filled,
  COLLECT {
    MATCH (t:Teacher)-[:TEACHES]->(g)
    RETURN {id: t.idx, name: t.name + " " + t.surname}
  } AS teachers
```

## GET /opinions

**Allowed:** Student, Teacher, Admin

Opinions are anonymous: the author is never returned. At least one of `teacher_idx` and `group_id` is required (`422` otherwise).

**Request**

No body; parameters go in the URL:

```http
GET /opinions?teacher_idx=T001
```

- `teacher_idx` (query, optional): only opinions about this teacher.
- `group_id` (query, optional): only opinions about this group.

**Response**

```json
{
	"opinions": List[Opinion],
	"avg_grade": Float?

	Opinion = {
		"id": String,
		"grade": Float,
		"content": String?,
		"submit": DateTime,
		"group_id": String,
		"course_code": String,
		"course_name": String,
		"g_type": String,
		"cycle": String,
		"teacher_idx": String,
		"teacher": String
	}
}
```

**Query**

The first MATCH depends on the parameters, so the query always starts from a node found through
its key index. With `teacher_idx` (optionally narrowed by `group_id`):

```cypher
MATCH (t:Teacher {idx: $teacher_idx})<-[:ABOUT_TEACHER]-(o:Opinion)-[:ABOUT]->(g:Group)
WHERE $group_id IS NULL OR g.id = $group_id
```

With `group_id` only:

```cypher
MATCH (g:Group {id: $group_id})<-[:ABOUT]-(o:Opinion)-[:ABOUT_TEACHER]->(t:Teacher)
```

followed in both cases by:

```cypher
MATCH (g)-[:OF_TYPE]->(gt:GroupType)<-[:HAS_TYPE]-(si:SubjectInstance)-[:INSTANCE_OF]->(su:Subject)
MATCH (si)-[:OFFERED_IN]->(ac:AcademicCycle)
RETURN o.id AS id, o.grade AS grade, o.content AS content, o.submit AS submit,
  g.id AS group_id, su.code AS course_code, su.name AS course_name, gt.g_type AS g_type,
  ac.year + " " + ac.season AS cycle, t.idx AS teacher_idx, t.name + " " + t.surname AS teacher
ORDER BY o.submit DESC
```
